# Authorized public test checkout

The optional /agenticcheckouttest alias is disabled by default. An authorized merchant must create a normal order using its registered receiving account with an unused payable amount between INR 1.00 and 1.99. Set AGENTIC_TEST_AMOUNT_MINOR to the exact reserved amount in paise (for example 101); defaults to 100. Set AGENTIC_TEST_ORDER_ID on the existing Agentic Pay service to that order's 48-character ID. The route redirects to the same order, never creates orders or reuses an amount. Only share the public alias with the intended tester: anyone with it can open the selected checkout while active. Do not set this alias to another merchant's order. Disable by removing the variable. Expired or submitted orders are not reopened. If INR 1.00 is already reserved, do not delete reservations; choose another unused decimal amount within the configured range. This is a single-order test alias, not a reusable fixed-amount order generator. Ordinary checkout remains unchanged. No visual or financial verdict is inferred.

## Reusable UAT entry
Set AGENTIC_TEST_AUTO=1 to enable automatic allocation on visible browser navigation. Uses the existing AGENTIC_LOGIN_MERCHANT_ID, requires exactly one registered receiving account, and never accepts merchant/account/amount input from visitors. No GET allocation: a same-origin POST allocates the lowest unused amount in 100–199 paise under the account row lock, using a secure browser cookie for idempotency. Refresh/reopening the alias reuses the active order; after submission or expiry a new visit starts a new session. Maximum five new orders per account per minute; permanently reserved amounts are never recycled. Public UAT pool is finite and can be exhausted by visitors, so share only with intended testers and disable after testing. No payment verification changes. Fixed-order mode remains the default.
