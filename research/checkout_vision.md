# Customer checkout vision indicator
Customer checkout has only Copy UPI ID, never I Paid, a manual upload, or diagnostic controls. The separate diagnostics route keeps its manual research action, and the merchant-authorized vision page remains separate.
After an observed browser return and successful read-only status response without a matching vision observation, the checkout displays a red cross and Vision not observed. This means no recognition result is available, not a determination that the payer did not pay. Polling continues and a matching server observation replaces red with green. No red before return; network errors do not create a new result. Read-only polling starts automatically, also on initial load and after copy, and stops on an observation, expiry, closure or revision change. No verification POST is triggered merely by return; the server observation publisher is independent of a customer declaration.
The green tick and "Vision recognized" require a matching server observation with exact order ID, VISUAL_SUCCESS, advance_research true, financially_verified false and checkout_changed false. No tick for return alone. The browser fixture tests no-click delayed observation and absence of a verification POST. This is not proof of automatic acquisition or debit; the authorized transport remains disabled until a legitimate source is established.

Receipt acquisition remains deferred and transport disabled by default. No new source or permissions are added; actual live split-screen observation remains unvalidated. No synthetic payment status can be promoted in production.
