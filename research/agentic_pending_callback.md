# Production return and pending status follow-up

The real-device checkout HTTP trace showed a status GET on return and a subsequent verify POST accepted with 202. That does not imply receipt acquisition. Previously the pending page made no subsequent reads, so delayed observations could not appear. This patch introduces bounded, read-only status polling after return and submission, including a reloaded pending checkout. It stops on recognized receipt, expiry/not found, changed checkout revision or 120 seconds; skips hidden pages and tolerates transient network errors. No new automatic financial decision, no image acquisition, no public observation ingestion. The browser test injects a synthetic API observation only in the local fixture after two polls. Backend still needs a legitimate receipt source and order-scoped observation publisher.
